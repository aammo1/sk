# Ad package templates

## Package shape

- Standard scope: six static ads, three concepts and two variations per
  concept. Variation A is the baseline; Variation B differs from A in exactly
  one named meaningful element (hook/headline angle or visual approach) while
  all other material elements stay constant.
- Three video scripts, one per concept, only when the user requested video at
  Checkpoint 1. Omit video concepts and scripts when the answer was no.
- One product-page brief with four gallery prompts (see `page-handoff.md`).

Change this standard scope only when the user explicitly approves a different
production scope. Package approval remains one gate even if the package is
presented in compact blocks.

Default concept families, adapted to each product:

1. The lived problem and its solution.
2. The main benefit demonstrated.
3. The strongest objection answered.

Every ad states its funnel objective: drive the click from Meta to the
product page where the order form lives. Nothing in this package is an
email step. Keep the same core promise across all six ads so the page
brief can repeat it consistently.

## Static ad card (one per variation)

Fill all of:

1. Concept and variation name, and the one changed element. Use this same
   label for the prompt and its Meta copy so campaign results stay traceable.
2. Objective and audience moment.
3. Hook: the first line the eye meets.
4. Visual direction: subject and product placement, environment and
   background, lighting, palette, typography, composition hierarchy;
   4:5 primary, with brief 9:16 adaptation notes for Stories/Reels.
5. Exact on-image text in the approved customer language (French by
   default): headline, one support line, CTA. Include the confirmed COD
   trust line only when confirmed, e.g. "Paiement à la livraison".
6. Message map: trace every step of the canonical strategy chain from
   `SKILL.md`, so the visual, proof and copy remain tied to the approved
   direction.
7. Production prompt in English embedding the exact customer-facing text,
   directly usable in the user's image tool.
8. Meta ad copy, separate from on-image text:
   - Primary text: the persuasive message above the ad.
   - Headline: a short benefit-led line below the creative.
   - Description: one concise supporting detail.
9. Negative constraints: preserve the real product's appearance; do not
   invent colors, logos, certifications, offers, testimonials,
   statistics, prices or comparisons.

## Video script template (one per concept)

1. Concept, objective, audience moment.
2. Duration 20–30 seconds, 9:16, hook within the first 2–3 seconds.
3. Scene table: Scene | Time | Visual | On-screen text (customer
   language) | Voiceover (customer language) | Sound.
4. Final CTA scene: the order action (select/order button and the actual
   confirmed next step), COD reassurance only when confirmed. Mention a
   confirmation call only when that is the merchant's real process.
5. Product fidelity notes and negative constraints.
6. Production instructions (shooting or AI generation) in English, with
   the exact customer-language on-screen text and voiceover embedded.
7. Meta primary text, headline and description, separate from on-screen text
   and labelled with the same concept name as the script.

## Copy guidance

- Headline ≈ hook ≈ first screen line: one clear promise in customer
  words. Benefits lead; features prove. One idea per ad.
- CTA variants in French: "Commander maintenant", "Commandez votre
  [produit]", add "— Paiement à la livraison" only when confirmed.
  No invented scarcity, discounts or guarantees.
- On-image text stays short: headline roughly eight words or fewer,
  support line roughly twelve or fewer, so it survives mobile crops.
- Meta primary text, headline and description are publishing fields, not
  instructions to render that copy inside the image or video. Keep each set
  aligned with its ad's single promise and confirmed facts.
- For Darija (Arabic script) on request: write the copy in Darija and
  note the script direction in the production prompt.

## Review check before presenting

- Each ad traces the canonical strategy chain from `SKILL.md`.
- Every product claim maps to an owner-confirmed fact, the product's own
  traceable source, fair direct demonstration, applicable technical evidence,
  or a genuine own-customer review. Competitor and category research may
  inform language or hypotheses but cannot prove this product's claims.
- Every CTA and trust line is real.
- Each variation differs in exactly one meaningful element.
- Prompts and scripts are paste-ready, with the exact customer-facing
  text embedded.
- Every static variation and each requested video has a separately labelled
  Meta primary text, headline and description.
- No generation, purchase or launch is performed by the prompt itself.
